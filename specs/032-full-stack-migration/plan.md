# Implementation Plan: Full-Stack Migration

**Branch**: `032-full-stack-migration` | **Date**: 2026-02-07 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/032-full-stack-migration/spec.md`

## Summary

Migrate the entire xtyl-creativity-machine from Python 3.11/FastAPI + Next.js 16 to a TypeScript-only pnpm monorepo: NestJS 10 + Fastify (backend), React 19 + Vite 6 + TanStack Router (frontend), with shared Zod schemas, Drizzle ORM (introspecting the existing Supabase PostgreSQL schema), BullMQ job queues (replacing Celery), and built-in observability (Pino + OpenTelemetry + Sentry). The existing database schema remains unchanged. Deployment targets Easypanel via Docker Compose. Cutover via 2-hour maintenance window.

## Technical Context

**Language/Version**: TypeScript 5.7 (all apps and packages)
**Primary Dependencies**:
- Backend: NestJS 10.x, @nestjs/platform-fastify, Drizzle ORM, BullMQ, Pino, @opentelemetry/sdk, @sentry/nestjs
- Frontend: React 19, Vite 6, TanStack Router, TanStack Query v5, Zustand, Tailwind CSS v4, shadcn/ui, Framer Motion, react-i18next
- Shared: Zod, @repo/shared (types, schemas, constants), @repo/observability (Pino, OpenTelemetry, Sentry)
**Storage**: Supabase PostgreSQL 16 (existing, no schema changes) + Cloudflare R2 (S3-compatible, existing) + Redis 7.x (cache + BullMQ)
**Testing**: Vitest (unit/integration), Playwright (E2E)
**Target Platform**: Easypanel (Docker Compose, Linux containers)
**Project Type**: Monorepo (pnpm workspaces + Turborepo)
**Performance Goals**: <100 concurrent users, API response times equal or better than current Python backend
**Constraints**: Must connect to existing Supabase PostgreSQL database with 35+ migrations and 30+ tables without schema changes. Must preserve all existing data. 2-hour maintenance window for cutover.
**Scale/Scope**: 3 apps (web, admin, api), 2 shared packages, 20+ API route modules, 36+ frontend routes, 30+ database entities

**Structure Decision**: Monorepo with `apps/` (web, admin, api) + `packages/` (shared, observability). This replaces the flat `frontend/` + `backend/` structure to enable code sharing via internal packages and unified tooling via Turborepo. The `supabase/` directory remains unchanged.

## Complexity Tracking

> **Constitution violations justified below**

| Violation | Why Needed | Simpler Alternative Rejected Because |
|-----------|------------|-------------------------------------|
| Technology Stack: Python/FastAPI + Next.js -> NestJS + React/Vite | This IS the feature. The migration targets a unified TypeScript stack for end-to-end type safety via shared Zod schemas, eliminating the Python/TypeScript boundary that causes contract drift. NestJS provides DI, modules, and structured architecture that FastAPI's flat file layout lacks at scale (27 services in a single directory). | Keeping Python backend means maintaining two languages, two dependency ecosystems, two CI pipelines, and manually synchronizing Pydantic <-> TypeScript types. The contract drift problem worsens with every new endpoint. |
| Project Structure: frontend/ + backend/ -> apps/ + packages/ monorepo | Monorepo with internal packages enables shared Zod schemas consumed by both frontend and backend from a single source. The `packages/shared` pattern eliminates type duplication. Turborepo provides dependency-aware builds. | The current flat structure cannot share code between frontend and backend without copy-paste or a separate npm package publication workflow. As the codebase grows (30+ models, 80+ schemas), keeping types in sync manually is unsustainable. |

> **Post-migration follow-up**: After migration completes, run `/speckit.constitution` to update Technology Stack and Project Structure sections to reflect the new TypeScript monorepo architecture (constitution v2.0.0).

## Key Technology Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| ORM | Drizzle ORM | Native pgvector support (`vector()`, `cosineDistance()`), `drizzle-kit pull` introspects existing schema, TypeScript-first, minimal runtime overhead. Prisma lacks pgvector support. TypeORM has no introspection. |
| Job Queue | BullMQ via @nestjs/bullmq | Direct Celery replacement. Same Redis backend. Official NestJS integration. Supports priorities, rate limiting, progress tracking, retries with backoff. |
| SSE Streaming | NestJS @Sse + raw Fastify reply | @Sse decorator for simple cases. Raw Fastify reply for workflow execution streaming (long-running, progress events from BullMQ). |
| Frontend Routing | TanStack Router (file-based) | Full type safety on params/search params/loader data. File-based routing via Vite plugin. Automatic code splitting. Layout nesting via `route.tsx`. |
| i18n | react-i18next | Largest ecosystem (6M+ weekly downloads). Namespace-based lazy loading. Direct migration path from next-intl's key-value JSON format. |
| Monorepo Tooling | pnpm workspaces + Turborepo | Internal Packages pattern (no build step for shared packages). Dependency-aware task runner. Docker prune for minimal production images. |
| Frontend Build | Vite 6 | Instant HMR, fast builds via esbuild/Rollup. TanStack Router plugin integration. No Next.js overhead for an SPA. |
| State Management | TanStack Query v5 (server) + Zustand (client) | Same as current system. No migration needed for state patterns. |
| Observability | Pino + OpenTelemetry + Sentry | Structured JSON logs (Pino), distributed tracing (OpenTelemetry), error tracking + performance (Sentry). Shared via @repo/observability package. |
