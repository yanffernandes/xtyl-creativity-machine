## 1. Copywriting Frameworks

### Decision: Use Multiple Proven Frameworks

**Rationale**: Different frameworks excel in different contexts. Using a variety ensures templates serve diverse marketing needs and user expertise levels.

### Selected Frameworks

#### 1.1 AIDA (Attention, Interest, Desire, Action)
- **Best for**: Ads, landing pages, email sequences, cold audiences
- **Structure**: Grab attention → Build interest → Create desire → Drive action
- **Use in templates**: Google Ads, Meta Ads, landing page hero sections

#### 1.2 PAS (Problem, Agitate, Solution)
- **Best for**: Urgent pain points, email marketing, social media posts
- **Structure**: Identify problem → Intensify urgency → Present solution
- **Use in templates**: Email campaigns, Facebook ads, blog posts addressing pain points

#### 1.3 BAB (Before, After, Bridge)
- **Best for**: Transformation products (fitness, education, SaaS)
- **Structure**: Current state → Desired outcome → Solution as bridge
- **Use in templates**: Instagram posts, testimonial content, case studies

#### 1.4 FAB (Features, Advantages, Benefits)
- **Best for**: Product descriptions, B2B marketing, sales pages
- **Structure**: What it is → How it works → Why it matters
- **Evidence**: 42% higher conversion rate when emphasizing benefits over features (Content Marketing Institute, 2022)
- **Use in templates**: E-commerce product descriptions, SaaS landing pages

#### 1.5 4Ps (Promise, Picture, Proof, Push)
- **Best for**: Long-form sales pages, product launches with strong claims
- **Structure**: Bold promise → Visualize outcome → Prove with testimonials → Push to action
- **Use in templates**: Long-form sales pages, webinar promotions

#### 1.6 StoryBrand Framework
- **Best for**: Brand websites, mission-driven marketing, building trust
- **Structure**: Customer is hero → They have problem → We're the guide → Call to action → Show success
- **Use in templates**: Brand stories, About pages, YouTube ads

## 3. Platform-Specific Best Practices

### 3.1 Google Ads (2025 Guidelines)
- Search Ads: 30 char headlines, 90 char descriptions
- Responsive Search Ads (RSA): 10-15 headlines, 4 descriptions
- Performance Max: Multi-format content across all Google properties
- Focus: High-intent keywords, immediate value communication

### 3.2 Meta Ads (Facebook/Instagram)
- First 1-2 lines critical for engagement
- Platform tone: Instagram (curated personal), Facebook (conversational)
- Carousel ads: 5 cards typical
- Stories: Quick value proposition (3-5 seconds)
- Brands with consistency: 450% more engagement

### 3.3 LinkedIn Ads
- Professional, value-focused tone
- B2B context: Thought leadership, case studies, data-driven
- InMail: Personalized, non-pushy approach
- Video ads: Professional case study format

### 3.4 Email Marketing
- Automated flows: 30X more revenue than one-time campaigns
- Welcome sequences: 3-email series typical
- Cart abandonment: 45% open rate, 21% click rate
- Subject lines + preview text: Critical first impression

### 3.5 Social Media Organic
- Hook importance: First 1-2 lines determine engagement
- Instagram Reels/TikTok: First 3 seconds decide watch/skip
- Twitter/X: Concise wit, thread format for depth
- LinkedIn: One idea per line, no hashtag walls

### 3.6 SEO & Blog Content
- Title tags: 50-60 characters (avoid truncation)
- Meta descriptions: 155-160 characters
- Numbers + power words in titles: Higher CTR
- Structure: H1/H2/H3 hierarchy for featured snippets

## 6. Variable Placeholder Standards

### Decision: Use `{{variable_name}}` Syntax with snake_case

**Standard Format**: `{{variable_name}}`

**Naming Conventions**:
1. **snake_case** for readability: `{{product_name}}` not `{{productName}}`
2. **Descriptive and specific**: `{{target_audience_demographics}}` not `{{audience}}`
3. **No special characters** except underscores
4. **Consistent terminology**: Use `{{brand_name}}` everywhere (not `{{company_name}}` in some templates)
5. **Plural for lists**: `{{features}}`, `{{pain_points}}`, `{{target_keywords}}`

**Standard Variable Categories**:

**Product/Service**:
- `{{product_name}}`, `{{product_category}}`, `{{key_features}}`, `{{main_benefit}}`, `{{unique_selling_proposition}}`, `{{price_point}}`

**Audience**:
- `{{target_audience}}`, `{{target_demographics}}`, `{{customer_pain_points}}`, `{{customer_goals}}`, `{{audience_awareness_level}}`

**Brand**:
- `{{brand_name}}`, `{{brand_voice}}`, `{{brand_values}}`, `{{company_mission}}`, `{{tone_of_voice}}`

**Campaign**:
- `{{campaign_goal}}`, `{{call_to_action}}`, `{{offer_details}}`, `{{urgency_element}}`, `{{landing_page_url}}`

**Content**:
- `{{content_topic}}`, `{{target_keywords}}`, `{{word_count}}`, `{{content_format}}`, `{{publication_date}}`

**Social Proof**:
- `{{testimonial_quote}}`, `{{customer_name}}`, `{{case_study_results}}`, `{{client_logos}}`, `{{awards_certifications}}`

**Rationale**:
- `{{}}` syntax compatible with Claude, Jinja2, most AI frameworks
- snake_case improves readability in prompts
- Standardization enables template reusability and user familiarity

## 7. Idempotency & UUID Generation

### Decision: Deterministic UUID from name + category

**Implementation Approach**:
```python
import uuid
import hashlib

def generate_template_uuid(name: str, category: str) -> str:
    """Generate deterministic UUID from template name + category"""
    combined = f"{name}:{category}"
    namespace = uuid.UUID('6ba7b810-9dad-11d1-80b4-00c04fd430c8')  # DNS namespace
    return str(uuid.uuid5(namespace, combined))
```

**Duplicate Detection Logic**:
- Check if template exists with same `name` AND `category` combination
- Query: `SELECT id FROM templates WHERE name = ? AND category = ? AND is_system = true`
- If exists, skip insertion (idempotent)
- If not exists, insert with generated UUID

**Rationale**:
- Deterministic UUIDs ensure same template generates same ID across migration runs
- Name + category combination allows same name in different categories (per clarification)
- Prevents duplicate entries while maintaining referential integrity

## 10. Migration Implementation Notes

### Alembic Migration Structure

**File naming**: `<timestamp>_seed_default_templates.py`

**Migration approach**:
1. Define templates as Python data structures (dicts/lists)
2. For each template, generate deterministic UUID
3. Check if exists (name + category + is_system=true)
4. If not exists, insert with prepared data
5. Log insertion count for verification

**Downgrade strategy**:
```python
def downgrade():
    # Delete all system templates seeded by this migration
    op.execute("DELETE FROM templates WHERE is_system = true")
    op.execute("DELETE FROM workflow_templates WHERE is_system = true")
```

**Rationale**: Clear upgrade/downgrade paths enable safe rollback if needed. Logging provides deployment verification.

## Alternatives Considered

### Alternative 1: Use AI to Generate Templates Dynamically
**Rejected because**: Quality consistency concerns, no expert curation, doesn't align with clarification (developer creates templates based on research).

### Alternative 2: Hardcode UUIDs Instead of Deterministic Generation
**Rejected because**: Harder to maintain, risk of collisions across environments, deterministic approach is cleaner and testable.

### Alternative 3: Use English Templates with Translation Layer
**Rejected because**: Brazilian Portuguese requires cultural adaptation, not just translation. Native language templates provide better user experience.

### Alternative 4: Create Separate Migration Per Category
**Rejected because**: Single migration is simpler to manage, atomic operation ensures consistency, easier rollback.
