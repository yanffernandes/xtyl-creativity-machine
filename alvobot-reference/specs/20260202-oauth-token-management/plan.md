# Implementation Plan: OAuth Token Management System

**Branch**: `20260202-oauth-token-management` | **Date**: 2026-02-02 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/20260202-oauth-token-management/spec.md`

## Summary

Implement robust OAuth token management to fix critical issues: Meta tokens not being exchanged for long-lived versions (60 days), Google services ignoring `needs_reconnect` flag causing infinite loops, and lack of circuit breaker protection. The solution adds Meta token exchange at OAuth callback, connection validity guards before all API operations, and an in-memory circuit breaker pattern.

## Technical Context

**Language/Version**: TypeScript 5.x
**Primary Dependencies**: NestJS 10.x, @nestjs/schedule, axios, @supabase/supabase-js
**Storage**: Supabase PostgreSQL (existing `connections`, `connection_logs` tables)
**Testing**: Jest (unit), Supertest (integration)
**Target Platform**: Node.js backend (Linux server)
**Project Type**: Web application (React frontend + NestJS backend)
**Performance Goals**: Token refresh < 2s, circuit breaker decisions < 10ms
**Constraints**: Rate limits (Google 10k/day, Meta 200/user/hour), single backend instance
**Scale/Scope**: ~1000 active connections, 30-min cron cycles

## Implementation Phases

### Phase 1: Circuit Breaker Foundation (P2 - FR-011 through FR-015)

**New Files:**
- `backend/src/modules/connections/interfaces/circuit-breaker.interface.ts`
- `backend/src/modules/connections/circuit-breaker.service.ts`

**Implementation:**
1. Create `CircuitState` enum (CLOSED, OPEN, HALF_OPEN)
2. Create `CircuitBreakerState` interface with rolling failure window
3. Implement `CircuitBreakerService` with:
   - `canRequest(connectionId)` - Check if requests allowed
   - `recordSuccess(connectionId)` - Reset on success
   - `recordFailure(connectionId)` - Track failures, open if threshold reached
   - `getState(connectionId)` - For debugging/monitoring
   - `reset(connectionId)` - Manual reset for reconnection flow

**Configuration:**
- Failure threshold: 5 failures
- Failure window: 5 minutes
- Cooldown period: 15 minutes

**Tests:**
- Circuit opens after 5 failures within 5 minutes
- Circuit stays closed with 5 failures over 10 minutes (outside window)
- Circuit transitions to half-open after cooldown
- Circuit closes on successful half-open test

### Phase 7: Circuit Breaker Integration (P2 - FR-012 through FR-015)

**Integration Pattern:**
```typescript
// Wrap all external API calls
async callExternalApi<T>(connectionId: string, apiCall: () => Promise<T>): Promise<T> {
  await this.connectionsService.assertConnectionValid(connectionId);

  if (!this.circuitBreakerService.canRequest(connectionId)) {
    await this.logCircuitBreakerRejection(connectionId);
    throw new ServiceUnavailableException('Circuit breaker is open');
  }

  try {
    const result = await apiCall();
    this.circuitBreakerService.recordSuccess(connectionId);
    return result;
  } catch (error) {
    this.circuitBreakerService.recordFailure(connectionId, error);
    throw error;
  }
}
```

**Apply to:**
- All Meta Graph API calls
- All Google API calls (Ads, Ad Manager, AdSense, Analytics, Search Console)
